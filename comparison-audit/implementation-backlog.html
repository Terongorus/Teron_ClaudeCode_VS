Tier 0

Correctness

A real defect, independent of everything else. Do it first.

BUG-1

“Active File” chip silently fails on Markdown Preview tabs

Inserts nothing, Claude receives zero context, and no error surfaces. Root-caused by switching the active tab to a normal code file, where it works correctly. Almost certainly VS’s active-document resolution not treating a Preview tab as a normal document.

Size S–M our:16 / our:17

Done whenThe chip either inserts the correct underlying file for a Preview tab, or says clearly that it can’t. The silent no-op is the actual bug — a visible message is an acceptable fix.

Tier 1

Style foundations

Cheap, compounding, no backend work. Grouped deliberately: they all touch the same XAML resources, so doing them together is far cheaper than one at a time.

ST-1

Define a design-token resource dictionary

Prerequisite for ST-2 through ST-5 — one place for the type scale, radii, surfaces and accent.

Size S§7blocks ST-2…ST-5

Done whenA single ResourceDictionary holds the scale, and the chat control references tokens rather than literals.

ST-2

Collapse the type scale from nine sizes to two

Baseline uses exactly 13px body (line-height 19.5px ≈ 1.5) and 11px chrome. We currently use nine: 9, 10, 10.5, 11, 11.5, 12, 12.5, 13, 14.

Size S§7 measured

Done whenNo more than two or three FontSize values remain in ClaudeCodeChatControl.xaml.

ST-3

Normalise corner radii to 5–6px

Baseline: 5–6px for controls and cards, 8px only on banner top corners. Ours: eight different values — 3, 4, 5, 6, 8, 10, 11, 15.

Size S§7 measured

Done whenRadii come from tokens and the long tail (10, 11, 15) is gone.

ST-4

Adopt the “one theme-invariant accent” rule

Measured in both themes: baseline re-derives every surface and text colour from the host theme and keeps exactly one constant brand colour — #C6613F, on the send button alone. Verified by flipping the isolated profile to light: body text #BBBEBF → rgb(59,59,59), header #191A1B → #F8F8F8, accent unchanged.

Size S§7 · real:20

Done whenEvery surface/text brush derives from a VS theme key, and exactly one hardcoded brand colour remains.

ST-5

Reconsider the solid terracotta user-message bubble

The single largest visual divergence. Baseline user messages have no bubble: background: transparent, border-radius: 0, full column width, padding: 14px 0 12px. Ours is Background=#D97757, white text, CornerRadius="10,10,2,10", right-aligned, MaxWidth=460. Baseline reads as a document; ours reads as a messenger app. This is the concrete instance of ST-4 — we spend the brand colour on the most-repeated element in the panel.

Size M§7 measureddepends on ST-1

This is the one item where “match the baseline” may be the wrong call. A VS extension has different visual conventions to a VS Code webview. The audit’s job was to make the divergence measured and visible — the design decision is yours.

Done whenA deliberate decision is made. Full parity is not required — but if the bubble stays, it should be a considered choice rather than an inherited default.

Order

Suggested sequencing

This list is genuinely ordered — each step either unblocks the next or is cheapest-first within a batch.

  1. BUG-1 alone. A real defect, independent of everything else.
  2. ST-1 → ST-2 → ST-3 → ST-4 as one batch. ST-1 is the prerequisite; done together they’re a single pass over the XAML resources rather than four.
  3. Tier 2 UX items, cheapest first. UX-5, UX-10, UX-1 and UX-7 are all trivial once ST-1 exists.
  4. GAP-2 → GAP-1. One small pattern closes five checklist gaps.
  5. ST-5 as a deliberate design decision, once the token work makes the alternative easy to try.
  6. FEAT-2 before FEAT-1. The diff tab is smaller, and both touch edit history.
  7. Everything else as its own scoped phase.

Already triaged as out of scope in Phase 0/5 — recorded here so they read as decisions rather than oversights: multiple simultaneous sessions · session groups · side-question panel · response rating · onboarding walkthrough · git worktree UI · browser, debugger and Jupyter MCP integrations.
